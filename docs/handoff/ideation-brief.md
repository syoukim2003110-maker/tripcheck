# TripCheck アイデア出し用ブリーフ

2026-11-14 時点。このファイルだけで、TripCheck の現状と制約が分かるようにまとめています。
この資料をもとに、**次に作る価値のある機能・体験のアイデア**を出してください。最後の「お願いしたいこと」に出力の形式があります。

- 本番サイト: https://trip.hikakunoshiori.com/ja/(英語版は https://trip.hikakunoshiori.com/)
- リポジトリ: https://github.com/syoukim2003110-maker/tripcheck(ブランチ `claude/free-place-resolution`)

---

## 1. どんなサービスか

**行きたい場所を選ぶだけで、そのまま使える旅の予定ができる Web サービス**です。

- 何日目に、どの順番で、どうやって移動するか(どの路線に乗り、どこで乗り換えるか)
- どこで食べるか、どこに泊まるか
- 地図

これらを1つの画面にまとめて出します。無料で、アカウント登録は要りません。スマホでの利用が中心で、日本語と英語に対応しています。

### 中心の利用者(資料からの仮説。調査で確かめたものではない)
行き先と行きたい場所はだいたい決まっているが、「どの日に、どの順で、どう移動して回るか」「店とホテルをどう組み合わせるか」を考えるのが面倒な旅行者。

### 片付けたい用事
> 行きたい場所が集まったとき、店やホテルとの位置関係も含めて日ごとの予定にしたい。収まらないなら、自分の希望を残しながら選び直したい。

### オーナーの最優先ルール
**土台が正しいこと。** 地図がちゃんと出る、移動が本当に最短、日の分け方が自然、画面に間違いがない。ここが崩れていたら、どんな機能を足しても意味がない。

## 2. 今できること(2026-11-14 時点、本番に反映済み)

### 行き先と場所を選ぶ
- 66都市から選べます。日本18都市(東京、京都、大阪、奈良、神戸、横浜、鎌倉、箱根、日光、金沢、名古屋、広島・宮島、福岡、長崎、札幌、函館、仙台・松島、沖縄)と、アジア・欧米の主要都市です。
- 各都市の有名な観光地を、写真付きのカードからタップで選びます。写真は Wikimedia Commons から取得しています。
- **名前で探して追加**できます。地図の検索で候補を出し、住所と中心からの距離を見て本人が選びます。種類は「場所/昼ごはんの店/夜ごはんの店/泊まるホテル」です。
- **リストをまとめて貼り付け**られます。1行に1つずつ貼ると、追加の前に「見つかった/選んでください/見つからない」の確認一覧が出ます。名前が一致しない候補は、本人が選ぶまで追加されません。
- 上限は24か所、7日です。

### 予定を組む(計算はすべて決まった規則で行い、AI は使っていない)
- 日の分け方と、1日の中の順番を、実際に近い移動時間をもとに最短になるよう探します。12か所までは全通りを比べます。
- 移動手段は、徒歩・電車・タクシー(目安)・バス(目安)から選びます。
  - 電車は、同梱の鉄道地図(Wikidata から作成、59都市)で、乗る駅・路線・乗り換え・降りる駅まで出します。
- 1日の時間は9:00〜18:00が基本です。ホテルがあれば8:30に出発し、夜ごはんの店は夜に入れます。
- 昼ごはんの時間を自動で入れます。昼ごはんの店を指定した場合は11:30〜14:00の間に入れます。
- **時間の条件(すべて任意)を入れると、必ず守ります。**
  - 「1日目に動き始められる時刻」と「最終日に切り上げる時刻」(ホテルへ戻る移動を含む)。
  - 場所・昼ごはんの店・夜ごはんの店ごとの「予約」(何日目の何時に開始)。その日のその時刻ちょうどに始まります。早く着く場合は空き時間として表示します。
  - 守れない場合は、別の時刻や別の日にずらして表示することはせず、「入りきらなかった場所」に理由を付けて出します(予約どうしが重なる、動き始める前、終了時刻を過ぎる、旅行の日数を超えている、など)。
  - 予約の時刻は「13:00 予約」と表示し、移動などの目安の時刻と区別します。
- 収まらないときは「あと何日必要」「この場所を外せば収まる」などを案内します。
- ホテルの「おすすめのエリア」を出します。候補の場所ごとに全日程を組み直し、移動が一番少なくなる場所を選びます。
- **出発日(任意)を入れると、天気予報を反映します。**
  - 2週間先までの予報を Open-Meteo から取得します。
  - 雨の日付に屋内中心の日が来るよう、日の並びだけを入れ替えます。同じ日に回る場所と、その日の中の順番は変えません。
  - 入れ替えたときは理由を表示します。

### 予定の画面
- 日ごとのタブに、日付・曜日・天気(予報)を出します。
- 移動の行は Google マップ風にしています。「10:00発 → 10:41ごろ着」、徒歩と路線の並び、徒歩の合計、乗り換え回数を出し、駅名つきの乗車カードは折りたたみの中に入れています。
- **都営線の区間には時刻表どおりの電車を出します**(出発日があるとき)。例:「14:26発 → 14:34着(光が丘行き)・次 14:32・14:38」。平日・土曜・休日のダイヤを日付から選びます。
- 日本の電車の区間には、Yahoo!乗換案内へのリンクを付けています(駅と時刻を引き継ぎ、実際の電車・番線・運賃が見られる)。日本以外の区間は地図アプリへのリンクです。
- **昼・夜ごはんの候補**を出します。
  - 日本では、ホットペッパーの掲載店を写真・ジャンル・予算つきで出します。昼はランチ料金の記載がある食事の店を優先します。
  - 「この店にする」で予定に入ります。
  - 海外は Apple マップの候補(写真なし)です。
- **カフェ休憩の候補**を出します。寄り道が少ない順で、日本ではホットペッパー掲載店の写真と予算を付けます。
- **ホテル候補**を出します(Apple マップ)。楽天トラベルや Booking.com で探すリンク付きです。
- 予定の場所を開くと、**営業時間・電話・公式サイトのカード**(Apple の場所カード)を見られます。
- 雨の予報の日は「屋内の候補」を、時間に余裕がある日は「近くのスポット」を出します。
- 地図について:
  - 見ている日の線だけを描きます。電車・徒歩・車の区別があり、道順が分からない区間は灰色の破線です。
  - ホテルとの往復は細く薄い線です。
  - 線の上に「電車 約20分」などの札を出します(重なるものは隠します)。
  - 店はフォーク、カフェはカップ、ホテルはベッドのアイコンです。
- その他の操作: 共有リンク、LINE で送る、印刷(紙のしおりとして全日程)、前回・その前の予定の再開。

### 見た目
青(#1967D2)1色と白・グレーを基調にした、簡潔な見た目です(Google、Apple、Airbnb のような方向)。以前の「紙の旅のしおり」風の装飾はやめています。

## 3. 変えられない前提(制約)

- **無料が前提**: 有料の API(Google Places の写真・口コミ、有料の AI など)は使わない方針です。
- **ホスティング**:
  - 静的サイト(Next.js の静的出力)を、レンタルサーバー(Xserver、PHP あり)に置いています。
  - 外部サービスの鍵は、サーバーの PHP 中継(apple.php)だけが持ちます。ブラウザに鍵は出ません。
  - データベースはありません。
- **アカウントなし**: 予定は利用者のブラウザ(localStorage)と共有リンクにだけ残ります。サーバーには保存しません。
- **使っている外部データ**(すべて無料枠または無料データ):
  - Apple Maps Server API: 検索、経路、移動時間、場所カード。中継経由で、1日の呼び出し上限あり。
  - OpenFreeMap / OpenStreetMap: 地図。FOSSGIS OSRM: 道順の予備。
  - Wikidata / Wikipedia / Wikimedia Commons: 観光地の一覧、写真、鉄道地図。
  - ホットペッパーグルメ Web サービス: 日本の飲食店の写真・予算。表記の決まりあり、取得した一覧の保存は不可。
  - 公共交通オープンデータ(ODPT): 都営線の時刻表(CC BY 4.0)。東京メトロは登録承認待ち。JR東日本はコンテスト限定の条件のため使えません。
  - Open-Meteo: 天気予報(鍵なし)。
- **正直さのルール**:
  - 時刻は「約」「ごろ」「目安」と明記します。
  - 持っていない情報(運賃、番線、混雑、評価、営業時間の確認済み、空室など)を作りません。
  - 予報は予報と書きます。
- **セキュリティ**: 読み込んでよい外部サイトの一覧(CSP)を固定しているため、外部のフォント・スクリプト・計測タグは足せません。
- **作り方の分担**: 見た目は ChatGPT/Codex、計算・データ・サーバー・反映は Claude です。

## 4. 分かっている弱点・まだできていないこと

- **日付と予約**:
  - 入れられる時刻は「1日目に動き始められる時刻」「最終日に切り上げる時刻」「予約(日と開始時刻)」の3つです。空港や駅そのもの(到着便の時刻、空港からの移動)は扱いません。
  - 中日(1日目と最終日以外)の開始・終了時刻は変えられません。
  - 予約は開始時刻だけです。「この時間帯のどこかで」や終了時刻の指定はできません。
  - 入りきらない場所が出たとき、外す場所の選び方は「必ず最少」とは限りません。
- **時刻表**: 都営線以外は時刻表がありません(東京メトロは登録承認待ち、JR は条件的に不可)。予定の時刻は時刻表ではなく目安です。
- **営業時間**: 予定の時刻と、その店や施設の営業日・営業時間は照合していません(カードで見られるだけ)。
- **写真**:
  - 海外の店・カフェ・ホテルには写真がありません。
  - ホテルの写真と料金もありません(国内は楽天のアプリ ID があれば可能)。
- **編集の安心感**: 変更前後の比較や、1つ前の操作に戻す機能はありません(ChatGPT の提案にあり、未着手)。
- **交通の範囲**:
  - 鉄道地図は Wikidata 由来のため、海外の路面電車などで路線名が欠けることがあります。
  - バスは目安だけで、経路は出せません。
- **天気**: 予報の取得元が1つだけです。止まると「取得できませんでした」になります(この資料を書いた日にも一時的につながらなくなった)。
- **共同編集はありません**: 共有リンクは入力のスナップショットで、開いた人の画面で計算し直します。
- **利用者の声**: 実際の利用者への調査や、効果の測定はまだしていません。

## 5. これまでに出た案(重複を避けるため)

- **ChatGPT の提案**(Google Design Sprint の Crazy 8s 形式)。採用状況は次のとおりです。
  1. まとめて貼る → **実装済み**
  2. 都市から写真で選ぶ → **現行の入口として維持**
  3. 地図に候補を置いて選ぶ → 未着手
  4. 制約(到着・出発時刻など)から先に組む → **一部実装済み**(動き始める時刻・切り上げる時刻・予約を守る。入力は予定の画面で行う)
  5. 困る点から2案を比べる → 未着手
  6. 変更前後の比較と取り消し → 未着手
  7. 店・ホテルを採用する前に、予定への影響を見る → 未着手
  8. 旅行中に「次の予定」だけを見る → 未着手
- **オーナーから出た要望**(対応済み):
  - 店やホテルの写真
  - カフェの提案
  - 天気の考慮
  - 電車の時刻
  - 地図のアイコンと移動手段の表示
  - 地図の線のごちゃつきの解消
- **2026-11-11 の競合調査**(旅行者の声69件)で多かった声:
  - 「行きたい場所リストをそのまま持ち込みたい」
  - 「移動時間が分かるのが便利」
  - 「オフラインで見たい」
  - 「印刷して持ち歩きたい」
  - 「同行者と共有したい」

## 6. お願いしたいこと

上の制約の中で実現できる、**旅行者が「これは使いたい」と思う機能や体験のアイデア**を出してください。

条件:
- 無料・アカウントなし・データベースなし・静的サイト+PHP 中継、で成り立つこと。外部 API なら、無料で使えて利用条件が合うもの。
- 「土台が正しい」を崩さないこと。根拠のない情報を出す案は不可。
- 5章で既に出た案は、深掘りするなら可。同じ案の繰り返しは不要。

出力の形式(1案ずつ):
1. **案の名前**(短く)
2. **誰の、どんな場面の困りごとを解くか**
3. **画面での見え方**(簡単な説明か、文字の図)
4. **必要なデータや仕組み**(どこから取るか、無料か、利用条件の注意)
5. **作る手間**(小・中・大)と、**価値**(小・中・大)
6. **土台を崩すリスク**と、その避け方
7. **確かめ方**(どうなれば成功か)

最後に、**最初に作るべき3案**を、理由と一緒に挙げてください。
